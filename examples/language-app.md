# Example: a language-learning app ad

A person asks a phone a question. The app replies sharply in German. The humor depends on the pause, reaction and camera angle. The brief changes the person and app, while keeping that interaction.

## Break it into jobs

| Layer | Plan | Check |
|---|---|---|
| Person asking/listening | Generate focused actor shots with performance/identity references | Correct words, glance, pause and reaction |
| App's German answer | Preserve approved reply audio separately | Full sentence and tail survive the edit |
| New app display | Build the conversation animation from product screenshots in Remotion | Exact interface and reply state |
| Phone shot | Fit the flat display to the original phone with Blender | Screen stays attached, hand remains in front |
| Captions | Preserve or recreate as their own layer | Wording, timing and stacking match |
| Final edit | Return the actor and phone shots to the reference's sequence | Picture and dialogue flow naturally |

If the model changes the person but leaves the old screen, repair the screen. If it speaks in the wrong voice, inspect the reference's embedded audio and the selected endpoint's voice support before retrying. A matching face image cannot fix unsupported audio conditioning.

In the tutorial's production, local UI and screen compositing preserved parts of the source that a whole-video edit struggled to change correctly. This is a method example, not a bundled reproduction: original footage, portraits, voices and paid outputs are not included. The historical jobs used a different provider; use OpenArt's current capabilities for your own run.
