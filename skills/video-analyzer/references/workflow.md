# From reference to finished layers

## Inspect and map

1. Read the user's latest script, requested changes, preservation constraints and any existing accepted edit. Work on new versions. Acquire or locate the reference video using the user's supplied file/link and an available authorized download tool; avoid downloading it again if already present.
2. Inspect the full picture and sound. Find exact shot boundaries from decoded frames/presentation timestamps, not rounded transcript times. Note expressions, gestures, lens direction, camera motion, speaker turns, captions, transitions and the final audio tail. Check for appended platform branding/end cards; exclude those from creative excerpts when appropriate.
3. Keep raw source files. Make prepared excerpts and a source map. For variable-frame-rate footage, use presentation timestamps until an explicit conform defines a constant frame rate. Never multiply time by a guessed frame rate and call it exact.
4. Fill a reference map: each image/video/audio file, its role and what should be ignored. Separate a performance reference from a character sheet. A synthesized unseen face angle is a hypothesis to inspect, not identity evidence.

## Plan the layers

Write a shot list with source range, target purpose, exact spoken text, speaker, required change and chosen method. Prefer focused generation for the person/action. Use Remotion for exact UI, captions and graphics, and local tracking/compositing for a filmed screen. Preserve successful sound, reactions and timing when the brief calls for it.

For each planned generation record the provider/tool/model, ordered references, precise prompt, exact dialogue, duration/resolution/aspect, native audio toggle, handling of embedded source audio, output path, estimated cost and acceptance checks. OpenArt is the intended route in this kit: inspect its actual exposed capabilities. Do not infer a direct Seedance endpoint, a model version, voice conditioning or a start-frame lock from a brand name. A unavailable field is a real constraint to report.

The user approves the bounded batch after seeing those inputs. Keep generation estimate, actual charge and refund separate. Reconcile timeouts/pending IDs before resubmission. Continue approved local edits without adding a new permission gate. A broader production or retry requires authorization if it is outside the existing scope.

## Build and inspect

Watch/listen to each full raw take before selection: exact words, repeated phrases, voice identity, lip movement, eyes, hands, pauses, unwanted music/text and closing tails. Do not use automatic word alignment as proof that the actual words are correct. Record selected/rejected status and the observable reason.

Use native picture/audio together at natural speed unless another method is requested. Preserve exact source-to-final cuts. Loudness can be matched with constant gain; inspect peaks and listen through adjacent joins. Similar loudness does not prove a matching voice, room tone or natural sentence. Do not revive speech stretching merely because generated footage is longer.

Build UI as coherent states with clear actions and exact text. Export flat screen pixels independently of camera movement. Fit them to each filmed shot using per-frame screen geometry and foreground masks. Do not apply camera shake twice. Keep caption glyphs separate; a rectangular source patch can accidentally retain the old interface beneath the words. Check the hardest blur/occlusion interval before extending the method.

For demonstrations, use real saved work or clearly label a reconstruction. The cursor must trigger visible state changes. Do not invent job receipts, connected account states, tool responses or a result that was not observed.

## Assemble and deliver

One owner assembles the timeline from handed-off assets. Record frame rates, frame counts, source ranges, timeline ranges, audio ownership and selected versions. Check cuts on both sides and frame-by-frame at difficult edges, then watch/listen continuously. Show comparisons at corresponding action/speech beats rather than matching arbitrary timestamps. Keep version/provider differences visible when they limit a comparison.

Deliver the review MP4, editable projects, dependency/version notes, render commands, audio stems where applicable and a concise QA report. Distinguish render/decode checks from human/perceptual acceptance. Do not advertise a guaranteed cost, exact likeness, voice similarity or a failure merely to strengthen a comparison. State what the output actually shows and which checks remain.
